# 凭证与配置参考

## 需要的凭证

| 凭证 | 来源 | 获取方式 | 是否必需 | 说明 |
|------|------|----------|----------|------|
| QQ `app-id` | [QQ 开放平台](https://q.qq.com) | 创建机器人应用后获取 | ✅ 必需 | 与现有配置相同 |
| QQ `app-secret` | QQ 开放平台 | 同上 | ✅ 必需 | 与现有配置相同 |
| QQ `token` | QQ 开放平台 | 同上 | ✅ 必需 | 回调验证用 |
| DashScope `api-key` | [阿里云百炼](https://bailian.console.aliyun.com) | 开通 DashScope 服务 | ✅ 必需 | Java Agent 已有 |
| Search API key | 第三方搜索 API | 根据使用的搜索服务 | ⚠️ 可选 | Java Agent 已有 |

**无需为 OpenClaw 本身付费或申请额外 key。**

## Java Agent 配置（不变）

```yaml
# application.yml - gateway 部分
gateway:
  qq:
    app-id: ${QQ_APP_ID}
    app-secret: ${QQ_APP_SECRET}
    token: ${QQ_TOKEN}
```

## OpenClaw 配置

```bash
# QQ Bot 插件
openclaw config set qqbot.enabled true
openclaw config set qqbot.appId "${QQ_APP_ID}"
openclaw config set qqbot.appSecret "${QQ_APP_SECRET}"
openclaw config set qqbot.token "${QQ_TOKEN}"

# 转发到 Java Agent
openclaw config set qqbot.defaultSkill "agent-relay"
```

# 风险评估

## 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| OpenClaw QQ 插件不稳定 | 中 | 高 | 保留现有 QQChannel 作为 fallback |
| Relay Skill 延迟过大 | 低 | 中 | 均为本地 HTTP 调用，延迟 <50ms |
| Java Agent 崩溃导致 QQ 失联 | 低 | 中 | OpenClaw 返回友好错误提示，不丢消息 |
| 双进程运维复杂 | 中 | 低 | docker-compose 统一管理，健康检查 |

## 安全风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Relay 端点被外部访问 | 低 | 高 | 仅监听 `127.0.0.1`，或加 Token 鉴权 |
| QQ 凭证在 OpenClaw 配置中明文 | 中 | 中 | 使用环境变量注入，不写配置文件 |

## 回滚方案

如果 OpenClaw 方案出问题，只需：

1. 停止 OpenClaw：`openclaw gateway stop`
2. 取消 `application.yml` 中 `gateway.qq.*` 的注释
3. 重启 Java Agent

现有的 `QQChannel` WebSocket 连接会自动恢复，QQ 用户无感知。

# 与现有方案的对比

| 维度 | 当前方案 (QQChannel) | OpenClaw 方案 |
|------|---------------------|---------------|
| QQ 接入方式 | WebSocket 直连 | WebSocket 直连（同一套官方 API） |
| 连接管理 | 自维护（QQChannel ~200行） | OpenClaw 内置 |
| AI 处理 | Java Agent | Java Agent（不变） |
| 多平台扩展 | 需写新 Channel | 插件市场直接安装 |
| 运维复杂度 | 单进程 | 双进程 |
| 可观测性 | 无 | Dashboard + Metrics |
| 灵活性 | 完全可控 | 受 OpenClaw 框架约束 |
