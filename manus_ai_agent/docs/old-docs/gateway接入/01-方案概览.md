# OpenClaw Gateway 接入方案

> 目标：通过 OpenClaw 作为中间层，为现有 Java Agent 接入 QQ 官方 Bot，同时保留 Java Agent 的全部 AI 能力。

## 当前现状

项目已有 QQ Bot 接入（`QQChannel.java`），通过 WebSocket 直连腾讯官方 QQ Bot API。
- ✅ QQ 官方 API（app-id + app-secret），无水封风险
- ✅ 支持私聊（C2C）和群聊（GROUP_AT_MESSAGE）
- ✅ 消息通过 `AgentGateway.chatSync` 路由到 Java Agent 处理
- ⚠️ WebSocket 连接管理、心跳、重连逻辑全在 Java 侧自行维护

## 为什么考虑 OpenClaw

OpenClaw 3.31（2026年3月）已**原生集成腾讯官方 QQ Bot 插件**，走的是同一套官方 API，不存在封号风险。它能提供：

| 能力 | 现状 (QQChannel) | OpenClaw |
|------|-----------------|----------|
| QQ 连接管理 | 自行维护 WebSocket | OpenClaw 内置（心跳/重连/会话恢复） |
| 多平台扩展 | 需逐个开发 | 内置 Slack/Discord/Telegram/飞书等 |
| 运维监控 | 无 | 内置健康检查、日志、Metrics |
| 插件生态 | 无 | ClawHub 插件市场 |

## 架构设计

```
┌──────┐   官方 QQ API    ┌──────────────┐   HTTP POST    ┌─────────────────┐
│  QQ  │ ←──────────────→ │  OpenClaw    │ ←───────────→ │  Java Agent     │
│ 用户 │                  │  (Node.js)   │               │  (Spring Boot)  │
└──────┘                  │              │               │                 │
                          │ QQ Bot 插件   │               │ AgentGateway    │
                          │ Relay Skill  │               │ ManusAgent      │
                          │              │               │ RAG / Tools     │
                          └──────────────┘               └─────────────────┘
```

- **OpenClaw** 负责：QQ 官方 WebSocket 连接、消息收发、心跳重连
- **Java Agent** 负责：AI 推理、工具调用、RAG、记忆管理（完全保留现有能力）
- **桥接方式**：OpenClaw 的 Relay Skill 通过 HTTP POST 调用 Java Agent 的 `/api/gateway/agent/chat` 端点

## 可行性结论

**可行**。基于以下已验证的事实：

1. ✅ OpenClaw 3.31 原生支持腾讯官方 QQ Bot API（与项目现有 QQChannel 使用同一套 API 和凭证）
2. ✅ OpenClaw 有完整的 Plugin/Skill SDK（TypeScript），可开发自定义转发逻辑
3. ✅ Java Agent 已有 `AgentGateway.chatSync` 同步接口，只需新增一个 POST 端点暴露它
4. ✅ 不需要额外付费 key
5. ✅ 双进程可容器化统一管理（docker-compose）
